Server and Controller

The Server schedules. Controllers execute.

The Server validates Git definitions and manages product state. A Controller in each cluster creates local Kubernetes Jobs. Logs stream to the Server, and declared artifacts are retained.

  1. 01

    Define Targets and Actions

    Keep operational definitions with the infrastructure code they control.

  2. 02

    Create a pinned Run

    Start manually, through the API, or from a named Git trigger. Slipramp snapshots the definition and commit before dispatch.

  3. 03

    Execute inside the cluster

    The local Controller creates the Job and reports its status. The Server never needs Kubernetes access.

Data boundaries

Your installation does not call home.

Slipramp has no product analytics. Repository contents, credentials, Run inputs and outputs, logs, and artifacts are not sent to the project maintainers. Cloudflare hosts this public website and provides ordinary traffic analytics for visits to slipramp.com.
